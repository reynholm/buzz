The original same-signed-bytes requirement is amended only for recovery: the first report content and route remain immutable, but an unaccepted expired report may become a freshly timestamped author-signed message. An accepted report, including one subsequently deleted, must never be recreated. The production DB floor stays armed. This design follows VISION's relay-owned access boundary and Nostr-first operations.

1. Add ephemeral Nostr recovery kind 20003. Content is `{original: Event, candidate: ReportStamp}`. The stamp contains only timestamp/ID/signature and reconstructs immutable fields from the original; both reconstructed events must be verified author-signed kind 9, with identical author, tags and content, and one canonical delivery UUID. Candidate has a current timestamp. The wrapper is author-signed, current, channel-scoped and bounded. Unknown servers cannot publish the nested candidate as a message. Route this command through shared ingest in both HTTP and WS; never fan out or store the wrapper. The selected candidate receives every ordinary message authorization, restriction, archive and thread check.
2. Add a community/author/UUID canonical delivery ledger. Transaction advisory lock serializes normal marked message writes and recovery. Under that lock: return an existing canonical record; otherwise adopt an existing original ID from the writer including soft-deleted rows; otherwise insert candidate + thread metadata + canonical record atomically. Store the signed canonical event for acknowledgment after redaction/retention. Reject key reuse across content/tags/routes. No event-floor bypass, replica read, or query-then-write gap. Attach the community deletion write fence and inventory/purge contract; maintain migration and desired schema parity. No automatic ledger expiry: one row per elected report, purged with its community. Coordinated relay upgrade is required; old writer processes do not participate in the lock.
3. Return the chosen signed event in the standard Nostr acknowledgment message, using `managed-delivery:` plus serialized Event; `event_id` names it. Canonical state drives duplicate receipts; only a newly inserted candidate fans out. Keep normal send/edit semantics outside the marker protocol.
4. CLI retains original signed event, optional recovery candidate stamp and canonical stamp in its bounded journal. Migrate v1 records safely. Before network use, persist a candidate identical except timestamp/id/signature; refresh an aged candidate without changing original evidence. Use recovery when original age exceeds 600 seconds, leaving margin to the 900/960 admission/storage limits. Validate canonical signature, author, UUID, content and exact tags against the original; persist confirmation before returning. Wrapper acknowledgments without this signed receipt fail visibly, including old-server ordinary acknowledgments. Normal timely v1-compatible publication remains supported. Keep original namespace, membership, limits, attempts and lock unchanged.
